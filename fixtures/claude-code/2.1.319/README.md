## Findings: S25

- **Which hooks carry `effort`** (54 of the run's 70 events): `PreToolUse` 11 of 11, `PostToolUse` 10 of 10, `PostToolBatch` 10 of 10, `Stop` 10 of 10, `SubagentStop` 12 of 12 (two `general-purpose` ones, ten internal ones with `agent_type: ""`), and **`PostToolUseFailure`** 1 of 1 (066). None of `SessionStart` (1), `InstructionsLoaded` (2), `UserPromptSubmit` (10, also the two `<task-notification>` turns 088, 093), `SubagentStart` (2) and `SessionEnd` (1) has it. No `PermissionRequest` occurred (every command was allowed). So only `PreToolUse`, `PostToolUse`, `PostToolUseFailure`, `PostToolBatch`, `PermissionRequest` (2.1.316 S19, S20), `Stop` and `SubagentStop` carry it, inside subagents too; every other hook never does, also when it fires after model calls (`UserPromptSubmit` 017, 027, …, `SessionEnd` 100).
- **`effort` is always `{"level": <string>}`**: no other key in any of the 54 events that have it, and `level` is a JSON string every time. The 2.1.319 binary describes it as "Active effort level for the current turn (e.g., \"low\", \"medium\", \"high\", \"xhigh\", \"max\"), after any silent downgrade for the selected model. Also exposed to hook commands and Bash as the CLAUDE_EFFORT env var." `log.sh` saw the name `CLAUDE_EFFORT` (names only, no values) in exactly the hooks that carry `effort`.
- **Every level appears in `effort.level`**, on every tool event of its turn: `medium` at the start, before any `/effort` (008–013; so sonnet's default is `medium`), `low` (018–023), `medium` (028–033), `high` (038–043), `xhigh` (048–053), `max` (057–062, 065–070 for the failing call, and the `Agent` turn, see below). Counts over the run: `low` 5, `medium` 10, `high` 9, `xhigh` 5, `max` 25.
- **Sonnet rejected or downgraded no level.** The TUI accepted every `/effort` without the "Change effort level?" dialog, and the payloads carry the level it set:
  - `/effort low`: "Set effort level to low (saved as your default for new sessions): Quick, straightforward implementation with minimal overhead", status line `○ low · /effort`
  - `/effort medium`: "Set effort level to medium (saved as your default for new sessions): Balanced approach with standard implementation and testing", `◐ medium`
  - `/effort high`: "Set effort level to high (saved as your default for new sessions): Comprehensive implementation with extensive testing and documentation", `● high`
  - `/effort xhigh`: "Set effort level to xhigh (saved as your default for new sessions): Deeper reasoning than high, just below maximum (on supported models)", `◉ xhigh`
  - `/effort max`: "Set effort level to max (this session only): Maximum capability with deepest reasoning. May use excessive tokens resulting in long response times or overthinking. Use sparingly for the hardest tasks.", `◈ max`. Unlike the others it is not saved.
  - `/effort auto` (end of the run): "Effort level set to auto", `◐ medium`. The stream has "Effort level et toauto": the TUI redraws only the cells that changed over the earlier answer on that line, so letters go missing; the full text is from the 2.1.319 binary.

  These are the texts of the raw terminal log (`tty/S25.log`, not in the repository), with its line breaks joined; the `effort answer` actions hold them without whitespace. The binary also has an answer for a capped level ("Effort '<level>' exceeds the cap for <model> set by your settings or organization; set to '<level>' instead"), which did not occur.
- **`PostToolUseFailure` carries `effort`** (066, `{"level": "max"}`, with `error` and `is_interrupt` as in 2.1.287 S12), like the `PreToolUse` (065) and `PostToolBatch` (067) of the same call.
- **The subagent with its own effort carries it; the inheriting one carries the orchestrator's session level, not the saved default.** The `Agent` turn ran at `max`, which `/effort max` sets for this session only; the saved default for sonnet was `xhigh` then (action `settings sonnet entry before the Agent calls`: `{"effortLevel": "xhigh"}`, from `/effort xhigh`). The orchestrator's events around the `Agent` calls carry `max` (073, 075, 076, 078, 079; `tool_input.effort: "high"` on 073/075 only). Subagent `abc55eb1…`, started with `effort: "high"`: `PreToolUse` 080, `PostToolUse` 081, `PostToolBatch` 082, `SubagentStop` 087 all `high`. Subagent `aaafa080…`, started without `effort`: 084, 085, 086, 089 all **`max`**, not `xhigh`. Both `SubagentStart` (074, 077) have no `effort`. The orchestrator's `Stop` while they ran (083), the `Stop` of the two hand-back turns (091, 094) and the internal agents' `SubagentStop` (090, 095, 097) stay `max`. So `effort.level` is the effort the agent that fired the event runs at: its own if its `Agent` call set one, else the orchestrator's current level. The raw subagent metadata (`subagents/agent-<id>.meta.json`, not in the repository) agrees: `"effort": "high"` for the first, no `effort` for the second, `pickedEffortModel: "claude-sonnet-5-5"` for both. (An earlier, discarded take of this run had the `Agent` turn at `low`, which `/effort low` had also saved, so it could not tell the two apart.)
- **`/effort` fires no hook.** Between a turn's last event and the next prompt's `UserPromptSubmit` there is only the internal agent's `SubagentStop`; no `ConfigChange` (subscribed by the capture project), although the TUI says the level was saved.
- **`/effort` saves the level per model** in `~/.claude/settings.json` under `modelSettings` (TUI: "saved as your default for new sessions"; `max` is "this session only"), and `/effort auto` clears it. The sonnet entry was empty before the run (`{}`), `{"effortLevel": "xhigh"}` before the `Agent` calls (so `/effort max` left the saved `xhigh` alone), and empty again after the closing `/effort auto`. 2.1.319 leaves the empty entry behind: an earlier attempt of this run the same day created it (before it, `modelSettings` had no sonnet entry), so `/effort auto` clears the level but not the entry. The earlier attempts are not curated: the driver then still waited differently for the hand-back turns, misread one `/effort` answer, or (the take before this one) ran the `Agent` turn at a level that was also saved.
- The status file shows `waiting` with `waitingFor: "dialog open"` within 35 ms after the Enter of five of the six `/effort` commands (`statusUpdatedAt` against the `send` action, logged right after the Enter), and `idle` again 60–125 ms later (014/015, 024/025, 034/035, 044/045, 098/099); for `/effort max` only an `idle` write 17 ms after the Enter (054).
- **Drift against 2.1.318** (S22 and S24 were haiku background sessions without tools): `SessionStart`, `InstructionsLoaded`, `UserPromptSubmit`, `Stop` and `SessionEnd` have the same keys, except `effort` on `Stop`, which 2.1.318's haiku runs could not have. `SessionStart` (`startup`) has `model: "claude-sonnet-5-5"`. The hooks 2.1.318 has no capture of, against their last capture: `PreToolUse`, `PostToolUse` and `PostToolBatch` (Bash) have the keys of 2.1.316; `PostToolUseFailure` has those of 2.1.287 plus `effort` (2.1.287 S12 ran on haiku, so this is not necessarily drift); the `general-purpose` `SubagentStop` has `last_assistant_message`, which the internal ones had since 2.1.316 and 2.1.289's `general-purpose` ones did not; `SubagentStart` and the internal `SubagentStop` are unchanged; the `Agent` call's `tool_input` has the new `effort` parameter (S16's `model` was not used here) and its `tool_response` the new key `canContinueAgent`. The status file has the keys of 2.1.316's interactive sessions (no `jobId`: not a background session). No key was lost.
